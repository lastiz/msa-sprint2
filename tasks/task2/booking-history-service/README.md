# Сервис истории бронирований

Сервис получает события о создании бронирований из Kafka и сохраняет историю в PostgreSQL.

## Бизнес-логика

1. Получить сообщение из топика Kafka (по умолчанию — booking.created).
2. Разобрать JSON и проверить данные бронирования. Некорректные сообщения записываются в лог и пропускаются с подтверждением обработки.
3. Сохранить запись в одной транзакции. Если запись с таким UUID уже существует, новое событие игнорируется.
4. Подтвердить сообщение после успешного завершения обработки. При ошибке БД сообщение не подтверждается и обрабатывается повторно.

## Данные истории

Запись содержит UUID события, идентификаторы бронирования, пользователя и отеля, необязательный промокод, процент скидки, цену, время создания бронирования и время получения события.

## Работа сервиса

При запуске сервис создаёт отсутствующие таблицы в БД, затем начинает потребление сообщений.
Настройки подключения к PostgreSQL, Kafka, топик, группа потребителей и режим отладочного логирования задаются через переменные окружения или локальный файл настроек.
