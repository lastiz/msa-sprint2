## Сервисы бронирования и истории бронирований

В рамках рефакторинга архитектуры из монолита были выделены два отдельных сервиса:

- **`booking-service`** — отвечает за всю логику, связанную с бронированиями.
- **`booking-history-service`** — сервис для хранения и обработки истории бронирований.

## Изменения в тестах (`regress.sh`)

Файл `regress.sh` был обновлен с учетом миграции функциональности на новые сервисы.

### Тестовые данные

Фикстуры с данными о бронированиях теперь создаются непосредственно в базе данных **`booking-service`**.

### Проверка `booking-history-service`

Добавлен новый тест, проверяющий наличие и корректность исторических данных непосредственно в базе данных **`booking-history-service`**.

## План миграции данных

После перехода на новую архитектуру основной сервис бронирования будет использовать собственную базу данных вместо базы монолита.
Поэтому перед переключением трафика необходимо перенести существующие данные о бронированиях из базы монолита в базу **`booking-service`**.

Миграция требует временного ограничения операций бронирования, чтобы исключить изменение данных во время переноса.

### Порядок миграции

1. **Остановить прием новых бронирований.**  
   Отключить возможность создания и изменения бронирований в монолите либо полностью остановить монолитное приложение на время миграции.

2. **Экспортировать существующие данные.**  
   Выгрузить актуальные записи о бронированиях из базы данных монолита.

3. **Импортировать данные в новый сервис.**  
   Перенести выгруженные записи в базу данных **`booking-service`**.

4. **Проверить корректность миграции.**  
   Убедиться, что количество записей и ключевые данные в новой базе соответствуют данным монолита.

5. **Переключить трафик.**  
   Возобновить работу системы с перенаправлением запросов бронирования на новый **`booking-service`**.
