# Сервис бронирования

Сервис Hotelio для создания бронирований и получения бронирований пользователя через gRPC. Данные хранятся в PostgreSQL, проверки выполняются через HTTP API монолита, события о новых бронированиях отправляются в Kafka.

## Бизнес-логика

Для создания бронирования передаются идентификаторы пользователя и отеля, а также необязательный промокод. Сервис последовательно проверяет:

1. Пользователь активен.
2. Пользователь не находится в чёрном списке.
3. Отель работает.
4. Отель считается надёжным по отзывам.
5. Отель не заполнен полностью.

Если условие не выполнено, бронирование отклоняется. Если внешняя проверка завершается ошибкой, бронирование не создаётся.

### Сохранение и события

Бронирование и событие о его создании сохраняются в одной транзакции PostgreSQL: либо сохраняются оба, либо ни одно. Ответ содержит идентификатор бронирования, пользователя и отеля, промокод, скидку, стоимость и время создания.
Фоновый обработчик отправляет сохранённые события в Kafka и отмечает успешную отправку в базе. При ошибке отправка повторяется.

## Получение бронирований

gRPC API возвращает список бронирований указанного пользователя, отсортированный по идентификатору бронирования. Идентификатор пользователя обязателен.
